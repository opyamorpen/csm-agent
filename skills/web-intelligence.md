# 客户公开动态联网检索

目标：从互联网公开渠道多角度检索客户最近 3 个月的动态，作为风险/增购分析的补充上下文。

## 触发条件

用户要求分析续约风险、增购机会、客户近况、公司背景，或明确要求"联网搜索 / 公开动态"时执行。工作台本地数据（csm-workbench-data）覆盖的是内部互动视角；本 skill 补充外部公开视角。

## 检索策略

1. **确定检索主体**：用会话绑定客户的名称。客户全称与简称（如"西安诺瓦星云科技股份有限公司"与"诺瓦星云"）分别尝试；简称通常召回更高。
2. **多角度分别检索**（用 web_search，一次一个角度，不堆砌关键词）：
   - 融资/投资："<客户名> 融资"
   - 重大合同与中标："<客户名> 中标" / "<客户名> 签约"
   - 产品发布："<客户名> 发布" / "<客户名> 新品"
   - 高管变动："<客户名> 高管" / "<客户名> 任命"
   - 组织变动与裁员："<客户名> 裁员" / "<客户名> 组织调整"
   - 负面舆情："<客户名> 处罚" / "<客户名> 诉讼" / "<客户名> 投诉"
   - 招聘动向："<客户名> 招聘"（扩张信号）
   - 行业政策："<客户名> 政策" 或结合客户行业
3. **时间窗**：默认 topic=news、days=90（最近三个月）。用户未特别要求时不要扩大到更久。
4. **控制次数**：总检索次数控制在 4-8 次以内，优先覆盖上述角度中最相关的；每次结果取前几条即可。

## 输出要求

- 每条动态必须带日期与来源 URL；无来源的不采用。
- 与客户无关的同名公司结果（行业/地域明显不符）须剔除并说明。
- **未搜到 = unknown**：某角度没有结果不构成任何正面或负面信号，不得据此推断（如"没有负面新闻"不能说"舆情健康"）。
- 搜索失败或未配置 API key 时，如实告知用户本次分析未包含公开动态，继续用本地数据完成分析。

## 落库

汇总完成后，把**有来源、有日期**的动态通过 `record_web_intelligence` 落库为 web_signal 证据（每条带 label/detail/occurred_at/source_url/category）。落库后，后续分析通过 `get_customer_profile` 即可读到，无需重复搜索。

## 与分析的结合

把公开动态与本地数据（风险评分、工单、会议记录）交叉印证，例如：融资/扩张利好增购假设；裁员/诉讼/高管变动加重续约风险；中标/新品发布提示扩容窗口。结论必须区分"有来源的事实"与"基于事实的推断"。
