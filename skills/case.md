# 客户案例对话精修

案例草稿由工作台后台任务生成（客户详情「生成案例」按钮或 `csm-agent case generate`）：服务端组装客户全量上下文（客户档案、时间线、已确认 Hemory 片段、证据信号），模型按五段叙事路径产出草稿。本 skill 处理**生成之后的精修环节**。

## 字段契约

见 `templates/case.json`。五段叙事：

1. `background`（客户背景）：行业、业务概况与合作起点的连贯叙述
2. `challenges`（痛点、现状与挑战）：合作前/合作中面临的核心困难
3. `requirements`（需求与要求）：客户明确提出的功能诉求、交付要求与服务标准
4. `solution`（解决方案）：问题如何被分析、设计、实施与协同解决，含关键实施路径
5. `value`（价值与成效）：已确认价值，量化优先，无量化写有据定性价值

## 精修流程

1. 用户会话中会给出待精修草稿的 `case_draft_id`、`case_version` 与五段当前内容。
2. 按 CSM 反馈修改：支持整稿重写，也支持**章节级重写**（如「只重写价值段，强调 XX」）——未要求修改的章节必须原文保留，不得改写。
3. 完成后调用 `confirm_write`：
   - `target_system=ones`，`record_type=case`
   - `fields` 必须包含 `case_draft_id`（原样带回）、`case_version`（原样带回）、`customer_id`、`customer_name` 与完整五段字段（含未修改章节的原文）
   - 可选带 `evidence_map`/`unknowns` 内部字段
4. CSM 批准后，服务端直接把五段内容写回 `case_drafts`（本地草稿更新，版本+1）；这不是外部系统写入。

## 写作纪律

- 客户叙事视角：客户是主角，按背景→痛点→需求→方案→价值的故事路径组织，不按数据来源罗列。
- 只写有证据的事实；多系统同一件事合并叙述，禁止会议流水账与工单流水账。
- 价值段禁止虚构 ROI、百分比或任何无证据数字。
- 未确认内容标「待确认」或不写；无法确定的关键信息写入 `unknowns`。
- 正文不出现内部系统名（Hemory、CRM）、风险评级/评分、工时统计、行动事项、联系人姓名、联系方式、合同金额。
- 发布到 ONES Wiki 由 CSM 在工作台完成（哈希审批门），本会话不执行发布。
