# 客户身份跨系统解析

目标：找到并锁定一个客户在三个系统里的唯一标识，避免串户。

## 输入
一个客户指代（可能是名称、简称、别名、或已给的某个 ID）。

## 步骤

1. **优先使用会话绑定**：若当前会话的客户上下文卡已有绑定标识（crm_customer_id 等），直接使用该标识，无需再查 MCP 解析身份。
2. **提取候选标识**：从用户输入中识别客户名称或任何已给出的 ID（CRM 客户 ID、项目名、工单号、录音主体名）。
3. **CRM 查主键**：从「可用 MCP 工具」清单中选择 CRM 服务器真实存在的客户查询工具（严格按清单中的工具名调用，不要臆造工具名），按名称/ID 精确或模糊匹配，取得 CRM 客户唯一 ID。
4. **项目管理（ONES）关联**：用客户名称或 CRM 中记录的关联项目，在项目管理系统的 MCP 工具里查到对应项目、以及该客户提交的需求/工单。
5. **录音主体匹配**：在录音系统的 MCP 工具里按客户名称/主体名查找录音主体，确认与 CRM/ONES 同一客户。
6. **交叉校验**：各系统的名称/唯一标识应能互相印证（例如项目描述里含客户名、CRM 联系人邮箱与录音参会人一致）。
7. **记录映射**：将最终确定的映射（CRM 客户 ID、项目、录音主体 ID）写进本次会话的上下文，供后续 skill 使用。

## 兜底规则（重要）
- 若名称模糊匹配到**多个**候选客户，**必须停下来向用户确认**是哪一个，绝不臆断。
- 若跨系统查无此人/串不到一起，明确告知用户"在 X 系统未找到该客户"，并询问是否有别名或 ID。
- 严禁在未确认唯一性时继续读取数据或回写。

## 输出
锁定唯一标识后，调用 `resolve_customer` 工具，把结构化字段提交到界面上的客户上下文卡（增量更新，后续读到新信息可再次调用）。字段示例：
```
resolve_customer({
  customer_name: "杭州云启科技",
  crm_customer_id: "cust_1024",
  ones_project: "云启-数据中台实施",
  recording_subject_id: "rec_subject_77"
})
```
并在对话里用一句话告知用户已锁定客户。
