# 客户身份跨系统解析

目标：找到并锁定一个客户在三个系统里的唯一标识，避免串户。

## 输入
一个客户指代（可能是名称、简称、别名、或已给的某个 ID）。

## 步骤

1. **提取候选标识**：从用户输入中识别客户名称或任何已给出的 ID（CRM 客户 ID、ONES 项目名、工单号、录音主体名）。
2. **CRM 查主键**：调用 `mcp__crm__*` 中的客户查询工具（如 search/query customer），按名称/ID 精确或模糊匹配，取得 CRM 客户唯一 ID。
3. **ONES 关联**：用客户名称或 CRM 中记录的关联项目，在 `mcp__ones__*` 中查到对应项目、以及该客户提交的需求/工单。
4. **录音主体匹配**：在 `mcp__recording__*` 中按客户名称/主体名查找录音主体，确认与 CRM/ONES 同一客户。
5. **交叉校验**：三个系统的名称/唯一标识应能互相印证（例如 ONES 项目描述里含客户名、CRM 联系人邮箱与录音参会人一致）。
6. **记录映射**：将最终确定的映射（CRM 客户 ID、ONES 项目、录音主体 ID）写进本次会话的上下文，供后续 skill 使用。

## 兜底规则（重要）
- 若名称模糊匹配到**多个**候选客户，**必须停下来向用户确认**是哪一个，绝不臆断。
- 若跨系统查无此人/串不到一起，明确告知用户"在 X 系统未找到该客户"，并询问是否有别名或 ID。
- 严禁在未确认唯一性时继续读取数据或回写。

## 输出
一段确定的三元组映射 + 各系统主键，例如：
```
客户: 杭州云启科技
CRM 客户 ID: cust_1024
ONES 项目: 云启-数据中台实施
录音主体 ID: rec_subject_77
```
