# 整理客户跟进记录

产出：一条或多条**跟进记录**，回写 **CRM**。字段契约见 `templates/followup.json`。

## 前置
先执行 `csm-identity-resolution`，拿到 CRM 客户 ID、ONES 项目、录音主体 ID 的映射。

## 步骤

1. **确定时间范围**：若用户未指定，默认"最近一次互动"或"本周"；不确定时向用户确认。
2. **并行读取三系统**：
   - CRM：客户信息、联系人、近期互动/机会（`mcp__crm__*` 读工具）。
   - ONES：该客户本期的需求、工单、工时记录（`mcp__ones__*` 读工具）。
   - 录音：该客户本期通话/会议转录文本与摘要（`mcp__recording__*` 读工具）。
3. **综合**：按 `templates/followup.json` 字段组织内容——
   - `key_topics` 从录音摘要 + 工单/需求标题提炼；
   - `customer_requests` 归纳客户明确诉求；
   - `action_items` 拆出行动项，并尽量标注负责人与截止日期（从对话或工单中找）；
   - `related_ones_items` 关联具体需求/工单编号。
4. **只写有依据的内容**：缺字段留空或注明"未提供"，**不编造**。
5. **成稿展示**：把完整字段渲染成可读草稿，调用 `confirm_write`（target_system=crm, record_type=followup）。
6. **批准后回写**：调用 CRM 的写工具创建跟进记录，回报记录 ID/链接。

## 质量要求
- 一行一个事实，可追溯到具体来源（录音/工单/需求）。
- 涉及客户承诺或我方承诺的内容，必须原样保留关键措辞。
- 工时数据若与跟进时间对不上，提示用户核对。
