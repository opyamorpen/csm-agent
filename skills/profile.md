# 生成客户档案

产出：每客户一份**客户档案**，回写 **ONES**。字段契约见 `templates/profile.json`。

## 前置
先执行 `csm-identity-resolution`，拿到 CRM 客户 ID、ONES 项目、录音主体 ID 的映射。

## 步骤

1. **读基础信息**（CRM）：行业、规模、关键联系人、当前阶段、使用产品、合同/续约信息。
2. **读业务动态**（ONES）：关联项目、需求、工单，提炼客户当前在做什么、卡在哪。
3. **读互动历史**（录音）：近期通话/会议摘要，提炼关注点与情绪/健康度信号。
4. **判断健康度**：综合续约状态、工单积压、需求推进、近期互动频率，给出 `health_score`（红/黄/绿）并写明依据。
5. **成稿展示**：按 `templates/profile.json` 组织，调用 `confirm_write`（target_system=ones, record_type=profile）。
6. **批准后回写**：调用 ONES 的写工具，在「客户档案」页面组创建/更新该客户页面；页面与关联项目/工作项建立关联（如 MCP 支持）。

## 更新语义
- 若档案已存在：**增量更新**，保留原有未变化字段，只改有变化的部分，并在页面里标注更新时间与来源。
- 若不存在：创建新页面。

## 质量要求
- 敏感信息（联系人方式等）仅在已授权范围内回写。
- 健康度判断必须给依据，避免空泛。
