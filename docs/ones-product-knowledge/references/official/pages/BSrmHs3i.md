## Confluence数据迁移

## 1.适用版本

此文档适用于「企业版-私有部署」的 ONES 系统

## 2.Confluence 迁移助手简介

ONES Confluence 迁移助手能够将 Server 版、Data Center 版以及 Cloud 版 Confluence 中的空间、用户、权限等数据迁移至 ONES Wiki 与系统中。迁移数据与迁移效果具体见下方：

| Confluence 数据类型 | 是否支持迁移 | 迁移效果 | 备注 |
| --- | --- | --- | --- |
| 空间 | 是 | 迁移空间名称 |  |
| 页面 | 是 | 保留文本、表格、图片、代码段、超链接、待办事项、引用等内容，可保留大部分文本样式 |  |
| 附件 | 是 | 保留页面中的上传的附件、通过部分插件生成的附件文件 | 如有超出 300M 的附件，需运维人员修改 ONES 系统的附件上限配置 |
| 宏 | 是 | 已支持的宏可迁移数据或保留样式（详见2.1）；未支持的宏以占位符显示 |  |
| 批注 | 是 | 保留批注对应位置和批注内容 |  |
| 页面树 | 是 | 保留页面树结构 |  |
| 主页 | 是 | 保留 Confluence 空间主页，如果主页无内容，则使用 ONES Wiki 的默认主页 |  |
| 博客 | 是 | 保留博客页面内容与权限配置 | 迁移后放置在「博客」节点下 |
| *孤儿页面 | 是 | 保留孤儿页面的页面内容与数据 | 迁移后放置在 「Confluence 特殊页面」 节点下 |
| 用户与用户组 | 是 | 迁移空间中的用户与用户组，保留用户的昵称、邮箱，保留用户组的名称与其中的用户 | - 邮箱格式错误用户，迁移时需手工设置邮箱或映射为 ONES 系统中已有用户<br><br>- 邮箱重复用户，迁移时默认合并为同一个用户，也可选择不合并，分别设置邮箱或映射已有用户<br><br>- 在 ONES 系统中被删除的历史迁移用户，迁移后状态默认为未激活状态<br><br>- 在 ONES 系统组织中已存在但状态为未接受团队邀请的用户，迁移后状态默认为未激活状态 |
| 页面相关人 | 是 | 保留页面创建者、编辑者、关注者 | 如果相关角色用户数据不存在，将使用迁移执行者账号进行替换 |
| 权限 | 是 | - 保留空间权限配置<br><br>- 保留页面权限配置，包括加密、共享设置<br><br>- 保留权限配置中的用户与用户组数据 | Confluence 空间主页的加密权限不保留 |

*孤儿页面：指在 Confluence 空间中父页面不存在的页面

#### 2.1.1 支持灵活的分批次迁移模式

ONES Confluence 迁移助手支持分批次规划迁移任务，可根据活跃度、价值度、业务关联度等方面灵活规划迁移，避免同时迁移大批量数据，造成迁移时间等待

## 3. 迁移前准备

- 确认迁移方式。如果您不需要迁移用户、权限等数据，仅保留空间中的页面、附件与页面树结构，可选择手工导入 Confluence 数据包（xml zip）的方式迁移，详见：[ONES Wiki 文档导入与导出](https://docs.ones.cn/wiki/#/team/6mRWUuNv/space/JrZtz5TS/page/A9cqnJrY)。如果您需要在迁移时进行批量操作，并同时保留用户、权限数据，推荐使用迁移助手进行迁移

- 检查 Confluence 版本与部署方式。迁移助手支持 6.x、7.x 、8.x Server/Data Server 版本，以及 Cloud 版本数据迁移至 ONES 私有部署服务，低于或高于上述版本的环境，请联系我们的技术支持或服务人员进行评估

- 确认 Confluence 数据用量。空间数量在 400 以下、总数据量在 500G 以下的 Confluence 环境推荐使用自助迁移工具进行迁移，用量较高的环境建议联系我们的人工支持服务，以便帮助您更好地评估与监控迁移过程

- 确认 Confluence 与 Jira 用户同步状态。如果 Confluence 的用户与 Jira 用户同步，请在迁移前确认用户同步已完成

- 准备 Confluence 超级管理员账号。迁移助手需要填写具备相应权限的账号及密码，以便连接 Confluence 服务

- 迁移前建议将 Confluence 切换为维护模式，避免在迁移过程中产生新数据

- 如果规划统一迁移，建议登录具备权限的迁移专用账号

- 【重要】如果通过 nginx 代理访问 confluence，请确保迁移执行过程中，在相关的 nginx 配置添加或者修改下面的配置

```Shell
client_max_body_size 0;   # 不限制单次请求体大小

proxy_connect_timeout 1d; # 调整反向代理的超时限制

proxy_send_timeout 1d;    # 调整反向代理的超时限制

proxy_read_timeout 1d;    # 调整反向代理的超时限制
```

## 4. 迁移评估

Confluence 迁移工具提供了数据用量评估工具，通过评估 Confluence 数据量给出迁移方式建议与环境配置参考，以便降低迁移异常风险。

进入配置中心，点击右上角「自助迁移」按钮，在弹窗中点击「开始评估」即可运行评估工具。如果此前已经评估过，在这里会展示前一次评估结果。

迁移评估工具仅支持评估 Confluence Server/Data Center 版本数据

[image: 9FoQC8Wi5Y6a0FHp5m98JMoGG2Gvehj4CSHdCaqfRCI.png; see source page]

如果您已经通过其他方式获知了待迁移的 Confluence 环境数据量等信息，也可以点击「新建迁移任务」直接开始迁移。

### 4.1 填写数据库信息

进入评估模式后，首先需要填写 Confluence 数据库相关信息。这些信息可以咨询 Confluence 管理人员或团队 IT 管理人员

[image: VGr9YI0cNLSWOP1xdBHuCClr2GFZ3ir1jWXSYNzL2qU.png; see source page]

- 数据库类型：根据 Confluence 所选的数据库类型进行选取，目前支持评估 Mysql、PostgreSQL、Microsoft SQL Server 三种类型的数据库，其他类型的数据库如需评估，请联系我们的迁移服务团队；

- 主机名：数据库主机名

- 端口：数据库端口

- 数据库名称：数据库的名称

- 数据库用户名及密码：填写具备数据表查询权限的用户名与密码，该信息仅用于提供给 Confluence API 执行数据用量的查询操作，我们不会存储这些信息。

### 4.2 评估数据用量

根据您填写的数据库信息，我们将分析用量情况，并提供合适的迁移方式建议，您可以参考评估报告中的空间更新时间、页面数量来规划迁移空间与迁移顺序。

[image: M-2MXumTkr26PYVuFqz2Nuaq1kNuVMbRQiKohV3LRHQ.png; see source page]

#### 4.2.1 查看评估结果

1. 数据迁移评估

包括迁移方式建议，迁移所需预估时间和环境配置建议

- 迁移方式：建议分为两种：自助迁移、人工支持服务迁移；

- 迁移所需预估时间：指在服务资源充足的情况下，一次性迁移全部数据的预估用时。以小时为单位；

- 环境配置建议：为了降低迁移异常风险，Confluence 服务器的磁盘剩余空间与内存需要与待迁移数据量匹配，这里会提供一些必要的扩容建议。

2. Confluence 使用情况

包括空间数量、用户数量、数据量、附件存储量以及最大空间数据量，这个表格有助于您了解您的 Confluence 数据用量情况，以便提前进行必要的迁移准备。

#### 4.2.2 下载评估报告

点击「下载评估报告」，您可以获得一个详细的数据表格，包括当前 Confluence 环境的数据用量概况，以及各个空间的用量清单。您可以参考该报告中的信息，例如：空间最近更新时间、空间页面数量等，进行迁移批次的划分。

## 5. 开始迁移

登录 ONES 团队管理员账号，在配置中心 - 导入数据 中，即可找到「从 Confluence 迁移数据」菜单

目前仅私有部署客户，云服务客户如需数据迁移，请联系我们的技术支持或服务人员进行评估

### 5.1迁移任务列表

#### 5.1.1 查看迁移任务列表

进入 Confluence 数据迁移功能页面后，在迁移任务列表中，可浏览或查询全部迁移任务，包括已规划但未执行的任务，以及已迁移的任务。已完成或正在进行的任务支持查看迁移报告，便于在分批次迁移过程中跟踪迁移进度。

[image: image - 2024-05-06T170716.667.png; see source page]

注意：  同一个 ONES 环境只能有一个正在迁移的任务

#### 5.1.2什么是迁移任务

Confluence 迁移支持分批次迁移，例如Confluence 中有 20 个空间，如果空间数据量较大，一次性迁移耗时较久，并且对迁移服务器造成性能压力。通过迁移任务拆分，可每次迁移 2 个空间，以降低迁移的耗时与等待。每一次迁移可被称为一个迁移任务。

利用迁移任务，管理员可根据迁移需求统一规划，安排时间进行分批次执行。在迁移测试阶段，亦可选取部分空间进行迁移效果验证。

- 任务名称：根据创建任务时间自动命名

- 任务状态：当前迁移任务的状态

  - 已就绪：已创建成功且经过数据检查但未执行的迁移；

  - 迁移中：正在执行迁移中的迁移

  - 已终止：迁移过程中因程序错误出现停止或人为停止；终止后可「查看迁移报告」

  - 已完成：迁移过程执行完毕，可「查看迁移报告」

- 迁移进度以空间数量表示，显示为：已迁移空间数量 / 本次迁移空间总数量

- 任务操作

  - 点击详情，可弹窗查看该任务中迁移数据的具体情况，弹窗中展示空间名称、空间关键字、数据包大小、数据包磁盘位置、页面迁移进度

  - 已就绪状态的任务，可选择「开始迁移」

  - 开始迁移的任务，可终止迁移，但仅能终止任务中未开始迁移的空间，已开始迁移的空间只能等待完成，不能取消或中断

### 5.2 迁移详情

点击迁移任务名称，弹窗展示迁移详情。包括开始迁移时间、Confluence 连接环境，以及任务中所迁移的空间，按照迁移状态分类显示；

- 空间迁移状态中，「迁移完成」表示迁移过程结束的空间，「迁移中」表示正在执行迁移的空间，「迁移异常」表示迁移过程中出现 Confluence 环境无法连接、无法获取数据包等错误导致迁移未能正常结束的空间，「准备迁移」表示正在从 Confluence 导出、正在下载 Confluence 数据包以及排队等待处理的未迁移空间

- 列表中展示展示 Confluence 空间名称、关键字、页面迁移进度以及数据包大小

- 如果迁移的 Confluence 空间无任何页面，会在迁移到 ONES Wiki 后自动创建空间主页，因此页面迁移进度会展示为 1/1

[image: image - 2024-05-06T170718.783.png; see source page]

### 5.3 特殊场景

- 迁移时可能会超出当前服务的 license 数量，不影响迁移

- 迁移后的用户不进行产品模块授权，导入后由管理员在账号设置中进行授权；

- 当已经有一个迁移任务正在执行时，其他已就绪的任务不可开始迁移

- 点击「开始迁移」，根据任务配置中的信息进行环境连接与数据获取，会等待一定的时间才会开始迁移；

- 点击「终止迁移」，仅能终止任务中未开始迁移的空间，已开始迁移的空间会继续执行

## 常见问题

###### 重复迁移的空间，是否会覆盖已经迁移的数据？

迁移是以空间为单位进行的，对于重复迁移的空间，会增量迁移一个新的空间，为避免重名，空间名称会增加编号后缀。

###### 迁移空间失败，并且迁移报告中提示：空间数据包导出失败时，该如何排查和解决？

出现该异常，可能由于 Confluence 服务使用的数据库连接超时，对应排查手段（适用于 MySQL 数据库）如下：

1. 确认原因：如果在日志中看到类似 Unable to rollback against JDBC Connection 、communications link failure 的错误，即为数据库连接超时

2. 解决方案：修改配置

修改 Confluence 服务所使用的 mysql 配置文件，一般为 /etc/my.cnf ，在 [mysqld] 配置节点下面添加或者修改 wait_timeout 和 interactive_timeout 为 mysql 的默认的值

```Plain Text
wait_timeout = 28800

interactive_timeout = 28800
```

###### 迁移空间失败，并且迁移报告中提示：空间数据包下载失败时，该如何排查和解决？

出现该异常，可能由于 nginx 配置导致的连接超时，请参照以下说明调整 nginx 配置

```Shell
client_max_body_size 0;   # 不限制单次请求体大小

proxy_connect_timeout 1d; # 调整反向代理的超时限制

proxy_send_timeout 1d;    # 调整反向代理的超时限制

proxy_read_timeout 1d;    # 调整反向代理的超时限制
```

###### 如果空间中包含引用自其他空间的页面链接，迁移完成后能否对应到 ONES Wiki 的目标页面？

可以的。迁移时会在当前任务和已经迁移完成的空间中，查找引用来源页面，并进行链接的替换。如果没有找到引用来源页面，会在迁移报告中列出引用位置页面和引用来源页面的原始链接，以便对应进行排查，见下图：
