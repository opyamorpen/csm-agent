## 模型配置

模型配置是私有部署版本启用 ONES Assistant 的前置步骤。管理员需要在此页面为系统接入 AI 模型服务，配置完成后 Assistant 才能正常运作。

进入路径：配置中心 > Assistant 配置 > 模型配置。

[image: ONES Assistant-配置-模型配置.png; see source page]

### 模型类型说明

ONES Assistant 需要配置多种类型的模型，不同模型在系统中承担不同角色。

| 模型类型 | 是否必选 | 作用 |
| --- | --- | --- |
| 文本生成模型 | 必选 | 提供对话、推理与内容生成能力，是 Assistant 的核心能力来源 |
| 数据索引模型 | 必选 | 提供语义检索与知识理解能力，用于对工作项和 Wiki 页面建立向量索引 |
| 语音识别模型 | 可选 | 将 Wiki 页面中的音视频内容转录为文本，参与知识索引构建 |
| 重排序模型 | 可选 | 在知识检索过程中优化结果排序，提升问答的相关性和准确性 |
| 联网检索服务 | 可选 | 为 Assistant 提供联网搜索增强能力 |

只有文本生成模型与数据索引模型同时配置成功后，Assistant 才能完整发挥能力。如果仅配置文本生成模型，Assistant 可以使用但知识库问答能力不会生效。

### 文本生成模型配置

文本生成模型是 Assistant 的核心能力来源。系统通过该模型完成自然语言理解、多轮对话推理以及研发场景中的智能生成。

#### 公有云配置

选择公有云模型时，需要填写对应平台提供的鉴权信息，并选择支持的模型名称。

| 提供方 | 必填信息 | 配置说明 |
| --- | --- | --- |
| OpenAI | API Key | Org ID 可用于区分成本来源 |
| Azure OpenAI | API Key、Endpoint、Deployment | 部署名称需与 Azure 后台一致 |
| MiniMax | API Key、Group ID | — |
| DashScope | API Key | — |
| Zhipu | API Key | — |
| Volcengine | API Key | — |
| Sensenova | Access Key / Secret Key | — |

配置完成后点击「校验并保存」，系统将自动验证模型服务连通性、权限及额度状态。

若模型支持推理过程输出，Assistant 在调用模型时将展示思考过程及耗时信息（即对话中看到的「思考完成(n秒)」）。

#### 私有部署配置

当企业使用自建模型服务时，可选择 OpenAI compatible API 方式接入。

| 参数 | 说明 |
| --- | --- |
| Base URL | 模型服务根路径 |
| 模型名称 | 必填 |
| API Key | 用于服务鉴权 |
| 上下文长度 | 建议不低于 8192 |
| 最大请求频率 | 根据业务规模设置 |

系统支持自动检测模型结构化输出能力。若模型不支持结构化能力，部分高级功能（如工作项批量创建、ONESql 生成等）将不可使用。

tip：选择具体模型时，建议参考 [模型服务选型建议] 中各提供方的对比说明。

### 数据索引模型配置

数据索引模型（Embedding 模型）是 ONES Assistant 构建知识理解与检索能力的基础。系统会基于该模型对工作项内容、Wiki 页面以及音视频转录文本进行向量化处理，并建立语义索引。当用户发起知识库问答或智能生成时，Assistant 会先通过语义检索获取相关上下文信息，再结合文本生成模型进行推理与回答。

#### 公有云配置

| 提供方 | 配置方式 |
| --- | --- |
| OpenAI | API Key + 模型选择 |
| Azure | API Key + Deployment |
| DashScope | API Key |
| Cohere | API Key |

#### 私有部署配置

| 参数 | 建议值 |
| --- | --- |
| 上下文长度 | ≥1024 |
| 向量维度 | 按模型能力填写 |
| 最大请求频率 | 按业务规模设置 |

#### 数据索引构建

首次完成文本生成模型与数据索引模型配置后，系统将自动开始构建知识索引。

| 项目 | 说明 |
| --- | --- |
| 索引范围 | 工作项与 Wiki 页面 |
| 构建期间 | Assistant 可使用但效果可能较弱 |
| 构建完成后 | 新增数据自动执行索引 |

索引构建时长与数据规模相关（工作项数量、Wiki 页面数量、音视频内容数量）。在索引构建期间 Assistant 可以正常使用，但回答质量可能受到影响。索引完成后，后续新增数据会自动执行索引。

### 语音识别模型配置

语音识别模型用于将 Wiki 页面中的音频或视频内容转录为文本，并参与知识索引构建。启用该能力后，Assistant 在知识问答时可以参考音视频信息，提高回答完整性。

当前支持的提供方：OpenAI、DashScope、私有部署。

系统支持设置最大音频处理时长，超过限制的文件将自动分片处理。

### 重排序模型配置

重排序模型用于在知识检索过程中优化结果排序，从而提升 Assistant 在复杂问答场景中的回答相关性与准确性。

支持的提供方：DashScope、Volcengine、Cohere。

配置时需要设置相似度过滤阈值（如 0.48），系统会过滤掉相似度低于该阈值的检索结果，确保返回给模型的上下文质量。

tip建议优先确保数据索引构建完成，使用推荐的 Embedding 模型，再启用重排序模型。如果数据索引未完成、Embedding 模型质量较低或检索命中数据较少，重排序模型可能无法明显提升效果。

### 联网检索服务配置

联网检索服务为 Assistant 的网络搜索能力提供支撑。配置后，用户在对话中开启 🌐 联网搜索开关时，Assistant 将调用该服务获取互联网信息。

当前支持的提供方为 Bocha.AI。配置时需要填写 API Key 并设置每次呈现大语言搜索数（默认为 3），即每次联网搜索返回的结果条数。

### 模型校验与保存

每种模型配置完成后，点击「校验并保存」按钮，系统会自动执行以下检查：

1. 验证模型服务连通性（能否成功建立连接）

2. 验证鉴权信息有效性（API Key 是否正确、账户是否有权限）

3. 验证额度状态（账户余额是否充足）

4. 对文本生成模型，额外检测结构化输出能力（function calling 支持情况）

校验通过后配置生效。如果校验失败，请参考错误提示逐项排查，常见原因包括 API Key 填写错误、账号未开通模型权限、额度不足、部署名称或模型名称不匹配等。

### 模型配置修改与索引重建

在已完成模型配置后，管理员可以随时进行调整。文本生成模型、语音识别模型、重排序模型和联网检索服务的修改即时生效，不影响历史数据。

数据索引模型（Embedding 模型）的修改需要特别注意。当更换 Embedding 模型时：

| 情况 | 建议操作 |
| --- | --- |
| 新模型与旧模型的向量维度一致 | 仅更新配置即可 |
| 新模型与旧模型的向量维度不同 | 选择「更新并重建索引」 |

如果向量维度发生变化但未重建索引，系统将无法直接使用原有索引，可能导致知识库问答异常。选择「更新并重建索引」后，系统会自动清理旧索引并使用新模型重新构建全部索引。

注意：如果系统中已存在向量索引数据，而新的 Embedding 模型维度发生变化，系统将阻止直接保存配置以避免向量库损坏。此时必须选择「更新并重建索引」方式提交。
