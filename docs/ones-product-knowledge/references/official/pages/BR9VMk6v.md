## 工时配置

## 1.功能入口

「团队管理员」可以在「配置中心」 - 「工时设置」进行配置

## 2.工时模式

不同团队对工作项工时的管理模式不同

- 部分团队会更关心整体业务的工时情况，通过整体业务的工时情况了解工作进度及健康程度，不太关心单个资源的工时情况；

- 部分团队则更关心团队资源的工时情况，通过业务下资源的工时情况了解整体工作的进度及健康程度，同时了解资源的工作安排及饱和度情况。

为了满足以上两种常见的团队工时管理模式，ONES现在支持两种工时模式：简单模式、汇总模式。

在简单模式下，团队可以针对工作项进行工时预估；而在汇总模式下，团队则是对成员进行工时预估，工作项的预估工时通过成员的预估工时汇总得到。

### 2.1 简单模式

在简单模式下，团队成员可直接填写工作项的预估工时和剩余工时。成员在工作项下登记工时将会消耗工作项的剩余工时直至剩余工时数值变为0，成员也可手动修改工作项的剩余工时，表示完成当前工作项还需多少时间。

[image: image.png; see source page]

需要注意，在简单模式下没有成员预估工时、成员剩余工时的概念，成员工时相关报表中的成员工时数据都是通过成员所负责工作项的工时数据得到的。

例如在迭代概念 - 成员剩余工时报表中，成员剩余工时=成员所负责工作项的剩余工时；又例如在预估工时日历中，成员每日预估工时=成员所负责工作项的预估工时/工作项的计划周期。因为没有成员预估工时的概念，在预估工时日历中只会通过工作项预估工时粗略的统计成员每日预估工时情况，因此也没有详细的工时卡片追溯成员预估工时情况。

[image: image.png; see source page]

在简单模式下，工作项工时不会细化到成员工时层面，只会对工作项整体工作量进行预估，工作项工时的填写、修改会相对便捷。但是成员工时层面的数据缺少使得团队较难精确追踪资源工作情况及资源饱和度情况。总的来说，简单模式适合更关注整体业务工作量，较少关注团队成员工作量的团队。

### 2.2 汇总模式

在汇总模式下，可单独计算成员预估工时和成员剩余工时，工作项的预估工时和剩余工时由工作项下成员预估工时和成员剩余工时汇总得到，成员不可直接修改工作项的预估工时和剩余工时，只能修改成员预估工时和成员剩余工时。

例如现有工作项A，成员a和成员b分别在工作项A上记录了自己的预估工时和剩余工时，其中成员a预估工时和剩余工时皆为3h，成员b预估工时为2h，剩余工时为1h，则通过计算可得工作项A的预估工时为5h，剩余工时为4h。

[image: image.png; see source page]

需要注意的是，在汇总模式下，成员在工作项上登记工时将会消耗成员自己的剩余工时直至成员自己的剩余工时值为0。这可能会造成成员登记工时之后工作项剩余工时值没有变化的情况。

例如现有工作项A，成员a在工作项A下添加了自己的预估工时和剩余工时分别为4h，此时工作项A的预估工时和剩余工时皆为4h，之后成员b在工作项A上登记了工时4h，此时工作项A的预估工时和剩余工时还是4h，因为成员b只会消耗自己的剩余工时，不会消耗成员a的剩余工时，成员b之前未设置自己的预估工时和剩余工时，系统将会认为成员b的预估工时及剩余工时为0h，所以在成员b登记工时之后，成员a和成员b的预估及剩余工时都没变化，这也就导致了工作项的预估及剩余工时没有变化。

为了避免以上情况，建议在预估工时的时候选择真正执行工作的成员。

[image: _EMK5YlJN; see source page]

在汇总模式下，因为有了详细的成员工时数据，所以成员工时相关报表都是由成员预估工时和成员剩余工时计算得到的，例如迭代概览-成员剩余工时报表以及预估工时日历。另外预估工时日历还支持查看、添加成员详细工时卡片。关于汇总模式下工时日历的更多介绍可参考「工时管理」下的工时日历部分。

汇总模式时，预估工时自动按工作日进行计算，并显示所选期间工作日，预估工时的所选日期期间必须包含工作日。具体计算逻辑可参考「工时管理」下的介绍

[工时管理](https://docs.ones.cn/wiki/#/team/6mRWUuNv/space/JrZtz5TS/page/WzLoebi9)

[image: image.png; see source page]

在汇总模式下，团队工时会精细到成员工时层面，团队不再对工作项进行整体预估，而是通过对成员预估工时后汇总得到工作项的预估工时。成员工时层面的数据使得团队能够更好地追踪资源工作情况以及资源饱和度情况，便于团队根据资源饱和度情况合理安排调整工作。总的来说，汇总模式适合关注资源工作情况的团队。

### 2.3 模式对比

| 功能模块 | 简单模式 | 汇总模式 |
| --- | --- | --- |
| 工时统计维度 | 工作项工时 | 工作项工时、<br><br>成员工时 |
| 工作项工时计算方式 | 可直接填写、修改工作项预估工时和工作项剩余工时，工作项登记工时由成员登记工时汇总 | 工作项预估工时、剩余工时、登记工时皆由成员预估工时、剩余工时、登记工时汇总得到，不可直接修改工作项工时，只可修改成员工时 |
| 工作项导入是否支持导入工时 | 支持导入工作项预估工时 | *支持导入成员预估工时 |
| 预估工时日历 | 根据工作项预估工时和工作项计划开始、计划结束时间计算工作项负责人的预估工时及饱和度。不可在工时日历查看具体的工时卡片 | 根据成员预估工时计算成员预估工时饱和度。可在工时日历查看、添加、编辑具体的工时卡片 |
| **预估工时权限 | 管理预估工时权限 | 管理自己的预估工时权限、管理所有预估工时权限 |

- *支持导入成员预估工时：汇总模式下导入的成员预估工时为工作项负责人的预估工时，导入的预估工时日期为“未规划日期”。

- **预估工时权限：从简单模式切换到汇总模式时，系统会将管理预估工时权限成员迁移为管理所有预估工时成员。管理自己的预估工时权限默认成员域为项目成员。从汇总模式切换到简单模式时，系统会将管理自己的预估工时权限成员与管理所有预估工时权限成员迁移为管理预估工时权限成员。

### 2.4 切换工时模式

在工时模式配置页面，用户可以查看团队当前使用的工时模式；如果需要切换团队工时模式，只需选中目标模式，点击「更新模式」即可。

- 从「简单模式」切换到「汇总模式」后，系统会将工作项当前预估工时、剩余工时迁移为工作项负责人的成员预估工时、成员剩余工时。

- 从「汇总模式」切换到「简单模式」后，系统将仅保留工作项预估工时、工作项剩余工时数据。 成员预估工时、成员剩余工时数据将被清空 ，请谨慎操作。

## 3.工作项工时汇总

### 3.1 汇总说明

进入「配置中心 - 工时设置 - 工时汇总」，根据工作场景的需要对工作项类型配置对应的工时汇总方式

[image: _89Eq1K93; see source page]

- 工时汇总可按工作项类型配置，并生效于所有项目

- 在配置为「不汇总」时，总预估工时、总已登记工时、总剩余工时、总工时进度、总预估偏差5个系统属性将隐藏

- 在配置为「汇总」时，总预估工时、总已登记工时、总剩余工时、总工时进度、总预估偏差5个系统属性将显示，并根据汇总规则计算

  - 当选择「汇总层级结构中的子层级工作项」时，可选择具体层级结构

    - 此时，汇总工时 = 自己的工时 + SUM(所选层级结构中子层级工作项总工时)

  - 当选择「汇总关联工作项」时，将统计所有关联工作项

    - 此时，汇总工时 = 自己的工时 + SUM(关联工作项工时)

### 3.2 查看汇总详情

配置了汇总方式的工作项列表下，在工作项详情页将展示「汇总工时信息」和「当前工作项工时信息」，点击「查看汇总详情」可查看汇总工时的详细情况
