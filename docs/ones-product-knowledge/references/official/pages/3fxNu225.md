## 工作项审批

### 功能场景

在研发协作中，需求评审、技术方案确认、版本发布等场景，往往需要在工作流的关键节点上完成内容确认，工作项才能进入下一阶段；审批通过后的内容也需要被锁定，避免后续被未经确认就修改，满足合规管控与基线管理诉求。

如果这些环节仅依赖口头沟通、消息通知或人工记录，容易出现审批过程不规范、关键内容未经确认就被修改、变更难以追溯等情况，影响协作的规范性和严谨性。

工作项审批能力用于解决上述问题。该能力将工作项关键节点的「内容确认」与「内容锁定」融入工作流管理：状态流转时需审批通过才能成功流转，并自动冻结审批属性；后续若需修改被冻结的属性，需发起变更审批，通过后才能修改成功。

### 功能介绍

#### 2.1 工作项审批规则

工作项审批通过审批规则定义"什么场景下、由谁审批、审批什么内容、审批通过后如何处理"。审批规则由项目管理员在项目设置中维护，每个项目可以创建多条规则，按需启用。

##### 2.1.1 启用工作项审批

工作项审批通过项目中是否配置「审批」组件来启用，不额外提供独立开关。

进入「项目设置」-「项目组件」，将左侧组件库中的「审批」组件拖拽至项目导航中，即可在该项目中启用工作项审批。

启用后，项目内可：

- 在「项目设置」-「工作项审批」中创建和管理审批规则

- 通过状态流转触发审批

- 在项目内的「审批」组件中查看本项目所有审批单

关闭审批组件（移除组件）后：

- 不影响已存在的审批规则，但会自动关闭所有已启用的规则

- 已发起的审批单可继续审批和查看

- 不支持继续发起新的工作项审批

- 工作项详情表单中已配置的「审批」控件展示不受影响

##### 2.1.2 审批规则管理和配置

进入「项目设置」-「工作项审批」，可在该页面新建、编辑、启用、停用、删除审批规则。

[image: image.png; see source page]

规则列表展示以下信息：审批规则名称、应用范围、最后更新时间、最后更新者、启用状态。

###### a. 创建审批规则

点击「新建审批规则」，按步骤填写审批对象、审批表单、审批流程和更多设置。

规则名称用于区分不同审批场景，建议采用清晰、可辨识的命名方式，例如：需求评审审批、版本发布审批、合规变更审批。

###### b. 配置规则信息

规则信息用于定义规则的应用场景和触发时机，包含以下配置：

审批对象：选择该规则适用的工作项类型，支持多选。

触发条件：定义在工作项的哪些状态流转上触发审批。每个工作项类型可配置多个触发条件，格式为「从状态 A 流转到状态 B 时触发审批」，其中状态 A 支持多选（含「任何状态」选项），状态 B 单选。

[image: image.png; see source page]



配置审批内容：定义该规则在审批通过后冻结的属性范围，决定了"哪些属性会被锁定、不可直接修改"。支持两种粒度：

| 粒度 | 说明 | 适用场景 |
| --- | --- | --- |
| 自定义审批属性 | 由管理员手动指定本规则要冻结的属性范围。未被指定的属性即使后续添加到工作项类型，也不会自动进入冻结范围。 | 需要精细化管控的协作场景，例如只需冻结需求的标题、描述、优先级等核心属性 |
| 整个工作项 | 该规则审批通过后，工作项的全部可冻结属性都会被冻结，且后续在工作项类型上新增的属性也会自动进入冻结范围。 | 需求基线控制、变更追溯等合规要求严格的场景，确保关键内容的完整管控不遗漏 |

支持作为审批属性的属性范围详见 2.1.3 支持作为审批属性的属性范围。

###### c. 配置审批表单

审批表单用于定义发起审批时需要补充填写的业务信息。可根据场景增加自定义表单字段，例如评审说明、变更原因等。

[image: image.png; see source page]

支持的控件类型包括：单行文本、多行文本、数字、附件、单选菜单、多选菜单、日期时间、说明。

###### d. 配置审批流程

审批流程用于定义审批由谁处理、如何流转、多人审批时如何判定结果。

审批流程支持两类节点：审批节点、抄送节点。

[image: image.png; see source page]

审批节点可配置以下内容：审批人类型、多人审批方式、审批人为空时的处理。

审批人类型

工作项审批支持以下审批人类型：

| 审批人类型 | 说明 |
| --- | --- |
| 工作项属性成员 | 从工作项的成员类属性中取值作为审批人，审批人随工作项内容动态匹配。适合按工作项责任人分发审批的场景，例如取需求的「技术负责人」「测试负责人」作为审批人 |
| 工作项所属项目的项目属性成员 | 从工作项所属项目的成员类属性中取值作为审批人，适合按项目维度统一治理审批职责 |
| 工作项所属项目的项目角色成员 | 从工作项所属项目的项目角色中取值作为审批人，适合按角色分发审批责任 |
| 指定用户 | 直接指定固定成员作为审批人，适合审批链路稳定、责任明确的场景 |
| 指定用户组 | 以用户组作为审批人来源，适合按组织分组配置审批职责 |
| 发起人直属上级 | 自动取发起人的直属上级作为审批人，适合常规汇报审批场景 |
| 发起人连续多级上级 | 按组织汇报链逐级取上级作为审批人，可配置最高层级，最多支持 16 层 |
| 发起人直属部门负责人 | 自动取发起人所在直属部门负责人作为审批人 |
| 发起人连续多级部门负责人 | 按部门层级逐级取负责人作为审批人，可配置最高层级，最多支持 16 层 |
| 提交人自选 | 发起审批时由提交人按规则选择审批人，适合审批对象不固定的场景 |

「工作项属性成员」「项目属性成员」「项目角色成员」是工作项审批特有的动态审批人来源，使审批人能够随工作项的内容和归属动态匹配，无需为每条工作项维护一份审批人名单。

多人审批方式

当同一节点的审批人为多人时，支持以下处理方式：

- 会签：需要所有成员同意后，该节点才通过

- 或签：任意一名成员处理即可完成该节点

审批人为空时的处理

当流程运行时未计算出有效审批人，可配置以下处理方式：

- 自动通过

- 转交给指定人员

- 转交给项目管理员

抄送节点

抄送节点用于在审批流程中通知相关方，但不参与审批决策。当审批流转到抄送节点时，系统会向抄送人发送通知并赋予审批单的查看权限。

抄送人类型与审批人类型相同，可灵活组合配置。

###### e. 审批更多设置

审批更多设置用于补充规则级处理细节，包含以下配置：

| 配置项 | 说明 |
| --- | --- |
| 审批通过后冻结审批内容 | 开启后，审批通过的属性会被冻结，需通过变更审批才可修改。关闭时，审批通过后属性值更新但不冻结 |
| 审批撤销 | 控制发起人在审批进行中是否可以撤销审批；可进一步限制"仅未处理时可撤销"或"任何时候都可撤销" |
| 审批驳回 | 控制审批人是否可以将审批驳回至提交人；允许时，可以选择重新提交后从被驳回节点开始审批，或重新依次审批。 |
| 审批人去重 | 同一审批人在流程中重复出现时的处理方式：不去重 / 连续出现时去重 / 出现多次时仅处理一次 |
| 审批意见是否必填 | 审批人执行同意、拒绝或驳回操作时，是否必须填写审批意见。 |

##### 2.1.3 支持作为审批属性的属性范围

审批属性是指可被审批规则冻结的属性。在配置审批规则时，「自定义属性」粒度需要管理员手动指定要冻结的属性范围；「整个工作项」粒度会自动冻结工作项类型下所有可冻结的属性。

并非所有属性都支持作为审批属性。不支持作为审批属性的属性主要包括：

- 计算类属性：值由系统基于规则自动计算或汇总而来，不可手动修改，例如停留次数、停留时间、公式计算、工时进度、发布进度等

- 基础不可变属性：例如 ID、创建者、创建时间、更新时间、评论

- 工时属性：登记工时、预估工时等

- 脚本属性：比如甘特图的里程碑、WBS父任务

#### 2.2 发起工作项审批

工作项审批通过两种方式发起：内容确认审批和内容变更审批。

- 内容确认审批：在工作项状态流转时由系统自动触发，用于在关键节点对工作项内容进行确认后再推进流程

- 内容变更审批：在工作项属性被冻结后，由成员手动发起，用于变更已锁定的内容

##### 2.2.1 发起内容确认审批

当工作项状态流转命中已启用的审批规则时，系统会自动弹出审批表单进入审批发起流程。例如：当审批规则配置为「从待评审流转到评审通过时触发」，成员将该需求的状态切换为「评审通过」时，审批表单会自动弹出。

[image: image.png; see source page]

[image: _81_fxhvE; see source page]

步骤表单与审批表单的关系

如果状态流转配置了步骤表单，会优先弹出步骤表单。步骤表单与审批表单分两步处理，互相独立：

- 仅存在步骤表单：弹出并提交步骤表单

- 仅存在审批表单：直接弹出审批表单

- 同时存在：先弹出步骤表单，填写并提交后立即写入工作项，再弹出审批表单进入审批发起流程

步骤表单字段在审批发起前就会写入工作项，不受审批结果影响；只有状态流转和后置动作会等到审批通过后才执行。

提交审批后的状态

发起审批后，工作项进入审批中状态。在审批处理中，工作项会受到相应限制：

- 工作项状态保持原状态，需审批通过后由系统自动流转到目标状态

- 审批规则中声明的审批属性会被临时冻结，不可在工作项详情、列表、表格、文档等任意视图中直接修改

- 工作项详情顶部、工作项列表、卡片视图、文档视图等位置会显示「审批中」标识

- 每个工作项同一时间只允许存在一个在途审批单

- 审批中的工作项不允许批量变更工作项类型、批量移动到其他项目

[image: image.png; see source page]

##### 2.2.2 发起内容变更审批

当工作项的审批属性已被冻结，需要再调整被冻结的内容时，需通过发起变更审批来修改属性值。变更值会随审批一起流转，审批通过后才会写入工作项。

两条发起入口

| 入口 | 触发方式 |
| --- | --- |
| 属性触发 | 在工作项详情中点击已被冻结的属性，系统提示「当前属性已冻结，发起变更审批」，点击后进入变更审批流程 |
| 工作项级入口 | 在工作项的快捷操作中点击「发起变更审批」，可一次选择多个属性进行变更 |

[image: image.png; see source page]

选择审批规则

进入变更审批流程后，需要先选择适用的审批规则。系统会根据"规则的审批属性范围"过滤出可用的审批规则：

- 属性触发入口：仅展示审批属性包含当前点击属性的规则

- 工作项级入口：仅展示审批属性与该工作项当前已冻结属性有交集的规则

- 历史上使用过的规则会优先排在前列

填写变更内容

选择审批规则后，右侧的「审批内容」面板会自动展示当前允许变更的属性，即"该规则的审批属性 ∩ 当前工作项已冻结属性"。也可以通过「+ 添加其他属性」入口扩展变更范围（仍需在所选规则的审批属性范围内）。

成员在面板中修改属性值、补充审批表单中的业务说明，然后提交变更审批。

变更值的写入逻辑

- 提交变更审批后，填写的变更值不会立即写入工作项，会随审批一起流转

- 审批通过后，由执行节点统一将变更值写入工作项

- 已冻结的属性变更后保持冻结；未冻结的属性是否新增冻结，由所选规则的「审批通过后冻结审批内容」开关决定

- 工作项处于变更审批进行态时，详情顶部及工作项列表会显示「变更审批中」标识

每个工作项同一时间只允许存在一个在途审批单，因此变更审批与内容确认审批不会同时存在。

[image: image.png; see source page]

##### 2.2.3 批量发起审批

工作项审批支持批量发起内容确认审批和批量发起变更审批，适用于一次性处理多条工作项的场景。

##### a. 批量发起内容确认审批

在工作项列表中批量修改工作项状态时，若命中的审批规则相同，可触发批量内容确认审批。

[image: image.png; see source page]

提交后，系统接入进度管理器异步处理，分两阶段执行：

1. 逐个工作项完成步骤表单的校验与写入

2. 步骤表单写入成功的工作项进入发起审批环节

执行结果页区分以下两类失败原因：

- 步骤表单写入阶段失败：步骤表单校验失败或写入失败

- 发起审批阶段失败：步骤表单已写入，但创建审批单时失败

##### b. 批量发起变更审批

在工作项列表中点击「批量发起变更审批」，可对多个已冻结属性的工作项统一发起变更。

发起流程：

1. 选择审批规则

2. 在工作项列表中勾选目标工作项（系统自动过滤出"至少有一个冻结属性、且无在途审批"的工作项）

3. 进入批量编辑表单，按工作项单条展示，可批量添加变更属性、勾选"同上"复用上一条值

4. 完成填写后统一发起变更审批

当所选规则的审批粒度为「整个工作项」时，批量编辑表单采用带搜索的选择器从工作项的可冻结属性中选择要变更的属性。

[image: image.png; see source page]

##### 2.2.4 处理审批

工作项审批发起后，可通过以下入口查看和处理审批：

- 审批中心：顶部导航的全局入口

- 项目内审批组件：查看本项目所有审批单

- 工作项详情：顶部「审批中」标识可直接进入审批单详情

审批中心用于从全局集中处理和跟踪与当前成员相关的审批，包含「待我处理、已处理、抄送我的、我发起的」四个视图，每个视图支持按审批规则、状态、所属项目、发起人、时间范围等条件筛选。

打开任一审批单，可查看审批信息、审批表单、审批内容（属性快照）和完整审批流程。变更审批单中还包含「仅查看变更项」筛选和「查看变更」入口，便于对比变更前后的属性值。

根据成员在审批单中的角色与当前节点状态，可执行以下操作：

- 同意 / 拒绝：完成当前节点的审批

- 加签：在流程中追加审批人，支持上加签、下加签、单人或多人

- 转交：将当前节点的审批转交给其他成员

- 驳回：将审批退回提交人修改，重新提交后按审批规则配置继续流转。

- 撤回：由发起人撤回审批，是否允许撤回取决于审批规则配置

[image: image.png; see source page]

审批被驳回后，审批单仍处于审批中。提交人可以在原审批单中更新审批内容并重新提交；审批流程会保留首次提交和重新提交版本，方便查看修改差异。

[image: image.png; see source page]

##### 2.2.5 审批通过后的自动执行与属性冻结

所有审批节点完成后，审批流程进入执行节点。执行节点由系统自动处理：

- 将工作项状态流转到审批规则中配置的目标状态

- 冻结审批规则中声明的审批属性

- 执行工作流的后置动作

执行节点的成功 / 失败与审批结果分开记录。若执行节点失败（例如目标状态已被其他途径变更），可在审批单中点击「重试」重新执行，无需重新走完整审批流程。

工作项处于审批进行中时，会在工作项详情顶部、工作项列表、卡片视图等位置显示「审批中」或「变更审批中」标识。审批属性同步显示冻结样式，hover 时提示对应的操作引导。

##### 2.2.6 审批控件 · 追溯审批记录

工作项详情可配置「审批」控件，用于集中展示该工作项的所有审批历史，帮助团队追溯关键内容的演进过程。

「审批」控件展示以下内容：

- 统计属性：发起内容审批次数、内容审批通过次数、发起变更次数、成功变更次数

- 历史审批单列表：该工作项发起过的所有审批单（含内容确认审批和变更审批），点击可跳转查看审批单详情

「审批」控件可添加到工作项的详情、空白标签页，展示位置灵活。

##### 2.2.7 审批通知

当审批流转到相关成员时，系统会发送通知。审批通知配置在工作项审批模块中管理，支持以下通知方式：

- 站内通知

- 邮件通知

- 第三方通知

通知触发场景包括：

- 审批到达待处理成员

- 审批被加签

- 审批被转交

- 发起的审批通过

- 发起的审批被拒绝

- 被抄送审批

点击通知可直接打开对应审批单详情。
