## 规划组件

## 规划组件简介

「规划」组件是管理团队任务列表的核心工具，在敏捷开发过程中不可或缺。通过这个组件，产品经理或项目经理可以通过简单的拖拽操作，将拟定好的待规划事项轻松安排到迭代中，完成迭代规划。

不仅如此，「规划」组件还提供了发布和史诗维度的规划方案，满足不同角色从各自视角进行规划工作。无论是针对单个迭代的任务分配，还是宏观层面的发布与史诗管理，「规划」组件都能确保每一次规划井井有条，助力团队高效达成目标。

## 功能特性

### 2.1 规划设置

项目添加「规划」组件后，项目管理员还需确认：

- 当前团队可用于规划的工作项类型，即设置数据范围。

- 谁能操作规划列表，即分配规划管理权限。

- 规划列表需要显示哪些属性，即设置列表属性。

- 管理规划的规模与进度，即设置预估规模和进度。

#### 数据范围

数据范围影响：组件里的工作项列表可以显示哪些数据，以及在组件内新建工作项时，可以选择新建哪些工作类型。默认范围为当前项目的需求和缺陷。你可以进入「项目设置」-「项目组件」页面，或点击组件右上角的「规划设置」，调整工作项范围，支持将其他项目的工作项类型设置到规划范围中。

[image: _KFSRPZL1; see source page]

#### 分配规划管理权限

具备「管理规划」权限的用户，可以对待规划事项进行拖拽操作。此权限默认分配给当前项目的成员。您可以进入「项目设置」-「权限配置」-「规划权限」页面，调整权限分配。

#### 设置列表属性

管理者可以将重点关注的属性配置在规划列表中显示，在更多关键信息的辅助下，高效完成规划操作。这样一来，团队成员能够更加直观地了解关键细节，提升整体规划的准确性和效率。。

[image: _ct9gjZQh; see source page]

#### 设置预估规模和进度

统一的度量衡能帮助管理者更精确地完成迭代规划。在「规划」组件中，管理者可以通过设置，将需求规模显示在规划列表中，并且可以跟踪由需求组成的发布或史诗的进度。这使得管理者能够更好地评估和管理项目进展，确保目标如期达成。

[image: _4WWiXw9Z; see source page]

### 2.2 按迭代规划

当产品经理拟定完成团队的待办需求清单后，项目经理即可召开迭代计划会，组织迭代成员对待办清单中的内容进行规模与交付标准的评估。评估完成后，项目经理即可根据资源与规模情况，创建迭代，并通过拖拽方式，将需求添加至迭代中。

[image: _yzWFM6ZE; see source page]



完成规划后，项目经理可以直接开始迭代，并持续跟踪迭代直至完成，完成的迭代将不再展示在「规划」组件中。

[image: _FHoU_TUr; see source page]



### 2.3 按发布规划

对于采用版本火车的团队，在固定的发布节奏中，项目经理需要合理规划每个发布的发布内容与迭代节奏，确保在每一个发布窗口顺利完成发版操作。在「规划」组件中，项目经理可以以发布的维度，将拟定的待规划清单规划到迭代中，确保每个发布被安排合适规模的需求。

[image: _q7EmemNG; see source page]



项目经理可在发布规划中，按史诗分组查看待规划内容，直观了解不同发布是否包含所需完成的业务目标（史诗）。

[image: _XAs3BSlp; see source page]



### 2.4 按史诗规划

作为产品负责人，通过史诗拟定好待规划内容后，可在「规划」组件中，以史诗的维度，将拆解的内容快速添加至迭代中，确保史诗被完整规划与实施。

[image: _L8fD6M_w; see source page]



在规划的过程中，可通过发布分组，结构化的查看与安排史诗的发布节奏。

[image: _R5T6pW8H; see source page]



## 其他特性

1. 在新建工作项时，用户可以自主选择打开完整的新建工作项弹窗，直接填写完整的工作项信息。

[image: _BuxanJXg; see source page]



2. 筛选器支持选择全部项目属性和选项，结果以项目进行分组，帮助用户精准选择不同项目中的筛选信息。

[image: _TESp8csM; see source page]



3. 支持shift键快捷选择大量工作项数据，减少重复的点击，高效完成规划工作。

[image: _lzBUFDq7; see source page]
