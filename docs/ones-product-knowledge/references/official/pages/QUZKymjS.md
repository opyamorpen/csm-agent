## 上下文范围引入

你可以通过编辑区的 + 按钮主动引入 ONES 中的数据作为上下文，限定助手的数据访问和分析范围。上下文以内联 Box 的形式嵌入指令中，与文本自由组合。

### 如何引入上下文

点击编辑区左下角的 + 按钮，打开上下文搜索面板。面板顶部提供四个类别筛选标签：

- 工作项 — 搜索并引入具体的工作项（需求、任务、缺陷等）

- 页面 — 搜索并引入 Wiki 页面

- 页面组 — 搜索并引入 Wiki 页面组（空间）

- 筛选条件 — 引入当前视图的筛选条件

在搜索框中输入关键词即可搜索对应类别下的数据。搜索结果以列表形式展示，点击任意结果即可将其作为上下文 Box 插入到编辑区中。

💡 你可以在一条指令中引入多个不同类别的上下文 Box。例如，同时引入一个筛选条件和一个页面组，让助手在特定数据范围内查找内容并保存到指定知识库。

### 上下文类别详解

#### 筛选条件

在 ONES Project 的工作项列表视图中，当前视图的筛选条件可以作为上下文引入。助手会读取筛选条件中隐含的项目、工作项类型、状态等约束，将其作为数据查询的边界。

引入筛选条件后，你的指令中无需再用文字描述"在哪个项目的什么状态的需求中"——助手会自动从筛选条件 Box 中获取这些信息。

```Plain Text
在 [🔍 当前筛选条件] 中查找跟 [💡确定迭代计划与 Sprint 安排] 相似的 [💡需求]
```

#### 工作项

你可以引入具体的工作项作为操作对象或参考基准。引入后助手可以获取该工作项的详情、动态、评论等信息。

常见用法包括：引入一个工作项让助手总结其动态、引入一个工作项作为"相似度搜索"的基准、引入一份需求文档对应的工作项进行拆解。

```Plain Text
当前工作项为 [💡【风险跟踪】高优先级需求推进跟进]，获取工作项全部动态并按以下要求总结：

1. 汇总当前工作项的全部变更记录与讨论内容

2. 按时间线梳理关键节点，并给出阶段性总结
```

#### 页面

你可以引入 Wiki 页面作为参考内容。助手会读取页面内容，用于问答、摘要、工作项提取等操作。

```Plain Text
基于 [📄 需求说明文档：自研系统账号体系与企业微信绑定] 生成对应的工作项
```

#### 页面组

页面组（Wiki 空间）可以作为知识检索的范围边界。引入页面组后，助手在进行知识问答时会优先从该页面组内检索相关内容，而不是在全局知识库中搜索。

```Plain Text
基于页面组 [📄 示例知识库] 中的内容回答：自研系统的 SSO 登录流程是怎样的？
```

你也可以指定页面组作为内容保存的目标：

```Plain Text
将分析结果保存到 Wiki 页面组 [📄 示例知识库] 中
```

### 自动上下文检测

除了手动引入上下文外，助手还支持自动检测当前页面的上下文信息。例如：

- 在工作项详情页中打开助手时，助手会自动识别当前工作项

- 在项目视图中打开助手时，助手会自动感知当前项目

- 在带有筛选条件的列表视图中，助手可以自动检测当前的筛选状态

自动检测到的上下文信息会反映在技能推荐中。例如在 Wiki 页面"需求说明文档"中，技能列表会包含"基于需求说明文档生成工作项"这样与当前页面内容直接相关的选项。

### 支持的上下文 Scope 体系

ONES Assistant 的上下文系统基于分层的范围架构，覆盖平台中的主要数据类型：

项目管理类（project）： 项目、工作项、工作项类型与状态、工作项属性字段、工作项评论、工时数据

知识管理类（wiki）： 页面组（空间）、页面

测试管理类（testcase）： 测试用例库、测试用例

用户与账户类（account）： 用户身份信息

每个范围决定了助手可以调用哪些工具以及可以访问哪些数据。当你引入特定类型的上下文时，助手会自动匹配对应范围下的工具来执行操作。
