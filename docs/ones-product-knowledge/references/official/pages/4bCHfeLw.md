## 工作项关联关系

## 1.什么是工作项关联关系？

关联关系主要用于配置工作项之间的关联关系，在关联工作项时使用，帮助清晰表达工作项之间的关系。例如，工作项 A 由工作项 B 复制而来时，为清晰说明两者复制与被复制的关系，可以通过自定义关联关系实现。目前，工作项关联关系通过“关联工作项属性”承载：

- 支持限制关联关系某一端可以选择哪些工作项类型

- 支持配置是否拆分关联属性，一条关联关系，会关联 1 个或 2 个“工作项属性“

  - 拆分关联属性：区分“发起方”与“被关联方”的属性名称。比如需求拆解为多个任务，需求上使用的属性为“拆解任务”，任务上使用的属性为“来源需求”。

  - 不拆分关联属性：不区分“发起方”与“被关联方”的属性名称。比如在需求里显示相似需求列表，则需求上使用的属性为“相似需求”。

## 2.配置关联关系

### 2.1 新建关联关系

在「配置中心」-「项目管理配置」-「关联关系」中，界面会列出系统里的全部关联关系，可直接从列表信息中了解该关联关系的”关联工作项类型“以及对应的”关联工作项属性“。

[image: image.png; see source page]

点击新建关联关系，在弹窗内选择关联关系类型，并点击确定，进入关联关系配置页面。具体配置参考下方配置案例。

1. 第一步：根据所需的业务流程，配置哪些工作项类型之间需要产生关联关系

[image: _6stcFsZA; see source page]

2. 第二步：配置是否需要拆分属性来描述工作项之间的关联，并配置属性的单多选情况

  1. 拆分属性：区分“发起方”与“被关联方”的属性名称。（使用场景：需求拆解为多个任务，需求上使用的属性为“拆解任务”，任务上使用的属性为“来源需求”）

  2. 不拆分属性：不区分“发起方”与“被关联方”的属性名称。（使用场景：相似需求之间的关联，则需求上只需要使用同一个属性“相似需求”来表示即可）

[image: image.png; see source page]

3. 第三步：配置是否需要传播可疑

- 拆分关联属性支持选择：1不传播可疑、2发起关联方修改，被关联方可疑、3被关联方修改，发起关联方可疑、4双向传播可疑

- 不拆分关联属性支持选择：1不传播可疑、2双向传播可疑

[image: image.png; see source page]

### 2.2 编辑关联关系

点击右侧编辑图标，可修改关联工作项类型和关联属性名称。

### 2.3 删除关联关系

点击右侧删除图标，可删除该关联关系。删除关联关系时，需要一同将关联工作项属性一并删除；如某个关联关系正在被任一工作项使用，则不可删除。

仅可删除自定义关联关系，系统关联关系不可删除

[image: image.png; see source page]

## 3.关联工作项属性

在「配置中心」-「项目管理配置」-「工作项属性」中，可以看到通过关联关系新建的关联工作项属性，在新建工作项属性时，也可以选择”关联工作项属性“，但需要通过新建关联关系来新建相关属性。

[image: image.png; see source page]

[image: image.png; see source page]

## 4.表单配置

### 4.1 配置表单展示样式

将”关联工作项属性“配置到表单后，支持配置显示样式为选择框、列表

- 选择框：不支持工作项之间调整排序，仅展示工作项标题信息

- 列表：支持列表之间手动排序，将重要的工作项置顶；其次支持配置工作项的列表属性，展示重要的属性信息

[image: image.png; see source page]

### 4.2 关联工作项控件

「关联工作项控件」可获取该工作项类型所有可用的关联关系，无需将”关联工作项属性“逐个配置到表单中。

注：”关联工作项控件“默认为列表样式，不支持配置为选择框样式，仅单个”关联工作项属性“支持

[image: image.png; see source page]

[image: image.png; see source page]

## 5.权限说明

新增「更新关联工作项」权限，若需要修改关联工作项属性，则需要同时拥有所有联动修改的工作项的「更新关联工作项」权限。

- 比如需求关联任务，需要同时拥有需求和任务的「更新关联工作项」权限，才可关联成功

[image: image.png; see source page]

## 6.工作项通知

配置”设置关联工作项“通知事件后，可接收所有”关联工作项属性“变更的通知，暂不支持自定义单个属性的通知事件。

[image: image.png; see source page]
