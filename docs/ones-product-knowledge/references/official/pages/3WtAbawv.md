## 快速入门

本章帮助你在最短时间内完成首次使用 ONES Assistant，了解对话界面的基本布局和交互方式。

### 前提条件

在使用 ONES Assistant 之前，请确认以下条件已满足：

- 你所在的组织已激活 ONES Assistant 功能。团队管理员可在侧边栏左下角的应用中心中找到 AI 类别，点击 ONES Assistant 进入详情页进行开通。

- 文本生成模型和数据索引模型已完成配置。私有化部署的组织需要管理员手动配置模型服务，详见 [配置与管理]。

- 你拥有 ONES 平台的有效账号和相应的功能权限。



## 访问入口与界面说明

### 打开 ONES Assistant

ONES Assistant 提供全局统一的入口。在 ONES 平台任意页面，点击右上角的 ONES Assistant 图标，即可打开右侧对话面板。

对话面板以侧边抽屉的形式展开，不会离开你当前的工作页面。你可以一边查看项目数据，一边与助手对话。

### 界面布局

对话面板从上到下分为以下区域：



- 顶部区域： 左侧显示新对话标题，右侧提供编辑、全屏展开、分享和关闭按钮。

- 对话区域： 展示你与助手之间的对话内容。新会话时，区域中央展示助手的欢迎语和技能推荐卡片。对话开始后，每条消息会标注发送者角色和时间戳，助手的回复中会包含思考过程、工具调用记录和最终结果。

- 编辑区： 位于面板底部，是你与助手交互的核心输入区域。编辑区内显示占位提示"描述指令或提出问题，输入 + 可搜索并插入 ONES 数据"。你可以在编辑区中自由组合自然语言文本和上下文 Box，构建完整的指令。编辑区左下角提供 + 按钮（搜索并插入 ONES 数据作为上下文）和网络搜索开关（🌐 图标），右下角为发送按钮。

#### 编辑区详解

编辑区的设计允许你将上下文信息和指令文本灵活混排。上下文以内联标签（Box）的形式直接嵌入文本中，而不是固定在独立的区域里。这意味着你可以像写一句话一样，把数据范围和操作指令自然地组合在一起。

例如，以下指令在编辑区中的呈现方式为：

```Plain Text
在 [🔍 当前筛选条件] 中查找跟 [💡确定迭代计划与...] 相似的 [💡需求]，

并总结这些需求，保存到 Wiki 页面组 [📄 示例知识库] 中
```

其中带有图标的标签是上下文 Box，它们分别代表：

- 🔍 筛选条件 Box： 引用当前视图的筛选条件作为数据查询范围

- 💡 工作项 Box： 引用具体的工作项作为参考对象

- 📄 页面组 Box： 指定 Wiki 页面组作为知识检索或保存的目标范围

你可以通过点击编辑区左下角的 + 按钮添加上下文 Box，也可以在输入文本时由助手自动识别当前页面的筛选条件并插入。每个 Box 右侧都有 × 按钮，点击可以移除该上下文。

灵活组合上下文 Box 和文本是提升指令准确度的关键。将数据范围（筛选条件、项目、页面组）直接嵌入指令中，助手能更精确地理解你要操作的数据边界，避免在全局范围内搜索。

### 技能推荐

打开 ONES Assistant 后，对话区域中央会展示助手的欢迎语和推荐技能列表。当前支持的快捷技能包括：

- 总结工作项全部动态 — 汇总当前工作项的所有活动记录

- 总结工作项全部评论 — 整理当前工作项的评论内容

- 总结最近七天动态 — 聚合近 7 天的工作项变更

- 查找相似工作项 — 跨项目语义搜索相似的工作项

- 创建需求 — 通过自然语言快速创建需求工作项

点击查看更多工具可以展开完整的技能列表。点击任意技能卡片即可快速发起对应的对话，无需手动输入指令。

💡 技能推荐会随着你在 ONES 平台中切换页面而动态更新。在工作项详情页中打开助手，推荐的技能侧重于工作项的总结和分析；在 Wiki 模块中打开，推荐的技能将与知识管理相关。

### 过程状态反馈

发送指令后，助手会在对话区域实时展示处理进展。一次典型的执行过程如下：

#### 用户指令

你发送的指令以蓝色气泡显示在对话区域中。如果指令中包含上下文 Box，发送后 Box 会转义为 [xxx] 文本格式，方便阅读和保留上下文现场。

#### 思考过程

助手在分析指令和规划方案时，会显示"思考完成（n 秒）"标记，表示该步思考耗时。点击右侧的 > 箭头可以展开查看详细的推理过程，包括助手如何理解你的意图、收集到了哪些信息、以及下一步计划。

一次任务中可能包含多个思考步骤。助手在每次工具调用前后都可能进行思考，以决定下一步操作。

#### 工具调用

助手调用 ONES 平台工具时，每个工具调用以带 ✓ 图标的卡片形式展示，显示工具名称（如"获取工作项详情"、"获取工作项动态"、"获取工作项评论"）。点击卡片右侧的 > 箭头可以展开查看该工具返回的 JSON 数据。

#### 生成状态

当助手正在基于收集到的数据生成最终回复时，对话区域顶部会显示**"正在生成内容..."的状态提示。生成完成后，状态变为"内容生成完成"**。

#### 最终结果

助手的回复以结构化的富文本形式展示。例如，一份工作项动态总结可能包含基本信息（标题、类型、状态、优先级、负责人等）、变更时间线、阶段性总结，以及后续行动建议。

回复末尾，助手通常会提供后续操作建议，例如"是否需要我帮您：查询依赖工作项的状态？协助推进状态流转？创建相关子任务？"——你可以直接回复继续操作。

#### 结果交互

每条助手回复的底部提供复制、重试、点赞/点踩等操作按钮，以及当前会话的上下文额度使用指示器。详见 [对话历史与会话管理]。



## 第一次对话——从提问到结果

本节通过一个完整示例，带你了解与 ONES Assistant 对话的全过程。

### 示例：总结工作项动态

假设你正在查看一个工作项的详情页，想要快速了解该工作项的全部变更记录和讨论内容。

在编辑区中，通过 + 按钮引入当前工作项作为上下文 Box，然后输入指令：

```Plain Text
当前工作项为 [【风险跟踪】高优先级需求推进跟进]，获取工作项全部动态并按以下要求总结：

1. 汇总当前工作项的全部变更记录与讨论内容

2. 按时间线梳理关键节点，并给出阶段性总结
```

其中 [【风险跟踪】高优先级需求推进跟进] 是通过编辑区插入的工作项上下文 Box，发送后会自动转义为文本形式。点击右下角发送按钮提交指令。

#### 助手如何处理你的指令

发送指令后，你可以在对话区域实时看到助手的处理过程（以下为某个任务的执行示例，实际情况会有所不同）：

第一步 — 思考： 助手分析你的指令，识别出需要获取该工作项的动态、详情和评论信息。点击"思考完成（2秒）"可以展开查看推理细节。

第二步 — 工具调用： 助手依次调用三个工具——获取工作项详情、获取工作项动态和获取工作项评论，分别获取工作项的基本属性、变更记录和讨论内容。每个工具调用以带 ✓ 的卡片形式展示。

第三步 — 思考： 助手整合三个工具返回的数据，规划如何组织输出内容。

第四步 — 生成结果： 助手输出结构化的总结文档。

#### 查看执行结果

助手的最终回复以结构化的富文本展示。在本例中，输出包含以下内容：

基本信息： 工作项标题、类型（需求）、状态（待规划）、优先级（最高）、负责人、创建时间等关键属性。

变更记录与讨论汇总： 按时间线整理的全部变更节点。

阶段性总结： 对工作项当前进展的概括。

后续建议： 助手会主动给出可执行的下一步建议，例如"确认依赖项状态——检查 WORKFLOWAI-11 和 WORKFLOWAI-14 是否已完成"、"启动规划工作"、"补充工时估算"等。

回复末尾，助手还会询问"是否需要我帮您"并列出具体的后续操作选项，你可以直接回复继续操作。

#### 对结果继续追问

ONES Assistant 支持多轮对话。你可以基于上一轮的结果直接在编辑区输入新的指令，助手会自动保持上下文。例如：

```Plain Text
帮我查询依赖工作项 WORKFLOWAI-11 和 WORKFLOWAI-14 的当前状态
```

助手会自动关联上一轮对话的上下文，无需你重复说明背景信息。

### 更多示例

以下是一些常见的指令示例，帮助你快速了解 ONES Assistant 的能力范围：

创建工作项：

```Plain Text
根据以下描述创建一个缺陷工作项：用户在导出 PDF 时，页面大小设置未生效，实际导出始终为 A4 尺寸
```

知识库问答：

```Plain Text
在产品需求文档中，关于用户权限管理的设计方案是怎样的？
```

数据查询与分析：

```Plain Text
帮我分析当前迭代的完成进度，按成员维度统计工时消耗
```

通知摘要：

```Plain Text
帮我汇总过去 7 天的通知，有哪些需要我关注的风险项？
```

结合上下文 Box 的复合指令：

```Plain Text
在 [🔍 当前筛选条件] 中查找跟 [💡确定迭代计划与 Sprint 安排] 相似的 [💡需求]，

并总结这些需求，保存到 Wiki 页面组 [📄 示例知识库] 中
```

### 编写有效指令的技巧

指令的清晰程度直接影响助手的输出质量。以下技巧可以帮助你获得更好的结果。

#### 明确任务目标

告诉助手你想要达成什么结果，而不仅仅是描述一个模糊的方向。

| 一般指令 | 更有效的指令 |
| --- | --- |
| 看一下这个工作项 | 获取工作项全部动态，汇总变更记录与讨论内容，按时间线梳理关键节点 |
| 写个周报 | 基于过去一周的工作项变更记录，生成一份项目周报，保存到项目 Wiki 中 |
| 有什么 Bug？ | 查询当前项目中状态为"进行中"的缺陷，按严重程度排列 |

#### 提供关键约束条件

在指令中包含项目名称、时间范围、筛选条件等关键信息，帮助助手精准定位数据。你也可以通过插入上下文 Box 的方式提供这些约束，效果更佳。

```Plain Text
✓ 帮我查询"支付模块"中最近 30 天创建的、优先级为"紧急"的缺陷

✗ 帮我看看最近有什么紧急的缺陷
```

#### 用编号列表描述多步要求

当你的指令包含多个要求时，使用编号列表可以帮助助手更清晰地理解每一项预期输出，避免遗漏。

```Plain Text
获取工作项全部动态并按以下要求总结：

1. 汇总当前工作项的全部变更记录与讨论内容

2. 按时间线梳理关键节点，并给出阶段性总结

3. 列出当前阻塞项和待办事项
```

#### 指定输出形式

如果你对结果的呈现形式有特定要求，可以在指令中明确说明。

```Plain Text
帮我统计各成员本迭代的工时投入，以图表形式展示
```

```Plain Text
将分析结果整理为一份 Wiki 文档，包含摘要和详细数据表格
```

#### 利用上下文 Box 减少重复描述

通过编辑区的 + 按钮引入项目、筛选条件或页面组作为上下文 Box 后，指令中无需再用文字重复描述这些范围。助手会自动读取 Box 中的数据边界。

```Plain Text
（已通过 + 引入当前项目和筛选条件作为上下文 Box）

帮我分析本迭代的需求完成率
```

详见 [上下文范围引入]。

#### 利用后续建议继续对话

每次回复后，助手通常会给出后续操作建议。你可以直接采纳这些建议继续对话，无需从零构思下一步指令。这在复杂的分析和排查场景中特别有用。

💡 如果你不确定助手能做什么，可以尝试直接用自然语言描述你的需求。助手会根据现有工具能力给出最佳方案，如果某项操作当前不支持，也会明确告知你。



## 对话历史与会话管理

ONES Assistant 支持完整的会话管理能力，你可以查看历史对话、恢复此前的会话继续交互，也可以随时开启新的对话。

### 查看历史对话

点击对话面板顶部的历史记录入口，即可查看所有历史会话列表。每条历史会话显示会话的创建时间和首条指令摘要，帮助你快速定位目标对话。

点击任意一条历史会话，即可加载该会话的完整对话内容，查看此前的指令、助手回复和工具调用记录。

### 继续历史会话

打开历史会话后，你可以直接在编辑区输入新的内容，基于此前的对话上下文继续交互。助手会自动加载该会话的历史上下文，无需重复描述背景信息。

例如，你昨天通过助手分析了项目进度，今天可以打开同一会话继续追问：

```Plain Text
昨天分析的那些延期工作项，现在状态有更新吗？
```

#### 上下文额度与压缩机制

每个会话都有上下文额度限制。你可以在助手回复底部的操作栏中查看当前会话的上下文使用情况，显示为"当前会话上下文额度已用 x%"。

当对话轮次较多或上下文信息量接近额度上限时，助手会自动进行上下文压缩，将已有的对话内容整理为一份进度摘要。这个过程对你是透明的——你不需要做任何额外操作，助手会在对话状态中显示"压缩中"的提示。

压缩后的上下文摘要保留了关键信息和任务进展，确保后续对话的连贯性不受影响。

💡 如果你发现上下文额度使用较高，可以考虑开始新会话来处理新的任务，避免在一个会话中堆积过多不相关的对话内容。

### 开始新会话

点击对话面板顶部左侧的新对话标题旁的编辑按钮，即可开始一轮全新的对话。新会话不会继承此前会话的上下文，适合处理与此前对话无关的新任务。

### 重试与反馈

每条助手回复的底部都提供一组操作按钮：

- 复制（📋）： 将回复内容复制到剪贴板

- 重试（🔄）： 重新执行本轮指令，助手可能会采用不同的推理路径产出不同结果

- 上下文额度指示器： 悬停查看当前会话已使用的上下文额度百分比

- 点赞（👍）/ 点踩（👎）： 对本次回复质量进行反馈，帮助持续改进助手的输出质量
