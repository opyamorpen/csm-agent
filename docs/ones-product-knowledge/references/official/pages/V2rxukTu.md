## 页面审批

### 功能场景

在企业日常协作中，制度文件、流程说明、知识页面、协同文档和数据表格往往先以在线协同的方式完成编辑，但在正式发布、跨部门确认和后续维护阶段，还需要解决版本确认、审批留痕、责任归属和变更管理等问题。

如果这些环节仍依赖群消息、邮件、线下沟通或人工记录，容易出现流程分散、页面内容与审批过程脱节、历史结果难以追溯等情况。

页面审批能力用于解决上述问题。该能力将页面内容管理从单纯的协同编辑，扩展为覆盖规则配置、审批发起、审批处理、结果反馈、历史记录和后续变更的完整闭环。



### 功能介绍

#### 2.1 页面审批规则

进入页面组设置后，可在“页面审批规则”模块中开启或关闭页面审批能力。

[image: image.png; see source page]



##### 2.1.1 配置未审批通过页面的可见范围

页面审批开启后，可单独设置新建的页面在「未审批」和「审批中」状态下的可见范围。可选范围包括：

- 仅编辑者、审批人和抄送人可见

- 拥有页面组查看权限的成员可见

该配置用于控制页面在正式审批完成前的可见范围。适用建议如下：

- 对制度、规范、公告草案等敏感内容，可选择较小范围可见

- 对需要先行共享讨论、再完成正式确认的内容，可选择页面组内成员可见



##### 2.1.2 审批规则管理和配置

页面组中可配置多条审批规则。规则列表通常展示以下信息：审批规则名称、最后更新时间、最后修改人、启用状态

###### a. 创建审批规则

规则名称用于区分不同审批场景，建议采用清晰、可辨识的命名方式，例如：页面发布审批、规范变更审批

[image: _ZyHnv19b; see source page]

###### b. 配置审批表单

审批表单用于定义发起审批时需要补充填写的业务信息。除系统自动带入的审批内容外，可根据场景增加表单字段。

支持的控件包括：单行文本、多行文本、数字、附件、单多选菜单、日期时间、说明

[image: image.png; see source page]

###### c. 配置审批流程

审批流程用于定义审批由谁处理、如何流转、多人审批时如何判定结果。

审批流程支持两类节点：审批节点、抄送节点

[image: image.png; see source page]

审批节点可配置内容：审批人类型、如何流转、多人审批时如何判定结果。

[image: image.png; see source page]

- 审批人类型

| 审批人类型 | 说明 |
| --- | --- |
| 指定用户 | 直接指定固定成员作为审批人，适合审批链路稳定、审批责任明确的场景 |
| 指定用户组 | 以用户组作为审批人来源，适合按组织分组配置审批职责 |
| 发起人直属上级 | 自动取发起人的直属上级作为审批人，适合常规汇报审批场景 |
| 发起人连续多级上级 | 按组织汇报链逐级取上级作为审批人，可配置最高层级 |
| 发起人直属部门负责人 | 自动取发起人所在直属部门负责人作为审批人 |
| 发起人连续多级部门负责人 | 按部门层级逐级取负责人作为审批人，可配置最高层级 |
| 提交人自选 | 发起审批时由提交人按规则选择审批人，适合审批对象不固定的场景 |
| 页面组管理员 | 由页面组管理员承担审批职责，适合页面组统一治理场景 |
| 绑定项目的属性成员 | 从页面组绑定项目的成员属性中取值作为审批人，适合与业务对象关联的审批场景 |
| 绑定项目的项目角色 | 从页面组绑定项目的项目角色中取值作为审批人，适合按项目角色分工审批的场景 |

- 多人审批方式

多人审批支持以下方式：

  - 会签：需要所有成员同意后，该节点才通过

  - 或签：任意一名成员处理即可完成该节点

-

- 审批人为空时的处理方式

当流程运行时未计算出有效审批人，可配置以下处理方式：

- 自动通过

- 转交给指定人员



###### d. 审批更多设置

审批更多设置用于补充规则级处理细节，配置包括：

- 审批发起后是否允许撤销

- 是否允许审批人驳回，以及重新提交后的审批方式

- 同一审批人在流程中多次出现时是否自动去重

- 审批意见是否必填

#### 2.2 发起页面审批

##### 2.2.1 发起入口

页面完成编辑并发布后，如页面尚未完成正式确认，页面头部会出现“发起审批”按钮。发起审批后，系统会自动完成以下处理：

- 自动生成审批单

- 自动带入当前提交的页面内容

- 根据审批规则计算审批流程和审批人

- 向相关审批人发送通知

审批发起后，页面进入审批中状态。在审批处理中，页面会受到相应限制，包括：

- 页面不可继续编辑

- 页面树会显示审批状态

- 审批处理中页面的部分操作会被限制，例如移动、归档、删除、重命名等操作不可用

在页面组内，可较直观地区分哪些页面正在审批、哪些页面尚未审批。



##### 2.2.2 批量发起审批

当存在一次性提交多份页面进行确认的场景时，可使用批量发起审批能力。可以通过以下入口发起：

- 从页面树中选择多个页面后批量发起审批

- 在审批内容中添加多个页面，依次生成多个页面审批

批量审批通常以父子审批单形式管理：

- 父审批单用于承载统一的发起信息

- 子审批单对应具体页面

- 不同页面的审批进度和结果可分别跟踪

##### 2.2.3 处理审批

当页面存在正在处理中的审批时，页面顶部还会出现审批中的提示标签；具备审批单查看权限时，可通过该提示直接进入审批详情。还可以通过以下位置打开审批单：

- 页面组内的页面审批列表

- 审批中心

- 页面更多菜单中的审批记录

审批单的查看范围受权限控制，通常仅对与该审批相关的成员开放，例如发起人、审批人或抄送对象。

###### 审批处理操作

根据成员在审批单中的角色与当前节点状态，可执行相应操作。操作包括：

- 同意/拒绝：用于完成当前审批处理

- 转交：将当前审批转交给其他成员处理

- 加签：在流程中追加审批人

- 驳回：将审批退回提交人修改，提交人更新页面内容并重新发起审批后，流程按审批规则配置继续流转

- 撤回：由发起人撤回审批，是否允许撤回取决于审批规则配置

[image: image.png; see source page]

##### 2.2.4 变更审批

当页面已经审批通过，后续如再次修改文档内容并提交，系统不会直接让新内容覆盖原页面，而是进入变更审批流程。

变更审批发起：

- 修改内容提交后进入审批流程；

- 变更审批期间页面同样会被锁定；

- 同一页面同一时间通常只允许存在一个审批；

- 审批单中可查看变更后的内容。



##### 2.2.5 审批中心

审批中心用于从全局快捷处理和跟踪与当前成员相关的审批。审批中心通常包含以下视图：待我处理、已处理、抄送我的、我发起的。

[image: image.png; see source page]



##### 2.2.6 审批通知

当审批流转到相关成员时，系统会发送通知。通知配置通在页面审批模块中管理，支持的通知方式包括：

- 站内通知

- 邮件通知

- 第三方通知

通知触发场景包括：

- 审批到达待处理成员

- 审批被加签

- 审批被转交

- 发起的审批通过

- 发起的审批被拒绝

- 被抄送审批

通知可直接打开对应审批详情。
